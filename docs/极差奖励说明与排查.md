# 极差奖励说明与“没有极差奖励”排查

## 一、极差奖励是谁拿的？

**极差奖励是“上级”拿的，不是“质押人”本人。**

- 当**用户 A** 去**质押流动性**（stakeLiquidity）时，合约会沿着 A 的**推荐人链**往上走。
- 对链上每一个**上级**，若满足条件，就会在 `stakePendingRewards[该笔质押ID]` 里记一笔**待发放**的极差奖励。
- 所以：**你有下级、且下级去质押了，你才可能拿到极差奖励**；你自己质押只会产生“静态收益”和“下级拿极差”的资格，不会直接给你自己发极差。

## 二、上级要满足什么条件才能被记极差？

合约里 `_calculateAndStoreDifferentialRewards` 对每个上级会检查：

1. **isActive == true**  
   即该上级自己**已经提供过流动性**（已激活）。

2. **有有效门票**  
   `userTicket[current].amount > 0` 且 `!uplineTicket.exited`。

3. **等级比前一级高**  
   按 `teamCount` 算出等级和 `percent`，只有 `percent > previousPercent` 才会产生“极差”并记一笔奖励（V1 需 teamCount ≥ 10 才有 5%，否则 percent=0）。

4. **最多 20 层**  
   推荐链上最多算 20 层；若某级 percent ≥ 45%（V9）则停止。

不满足以上条件的上级，不会被写入 `stakePendingRewards`，也就不会有这笔极差。

## 三、极差什么时候真正发到上级手里？

极差先存在 `stakePendingRewards[stakeId]` 里，**不会自动发**，要等：

- **质押人（下级）** 在这笔质押**周期结束后**，去点 **「领取收益」**（claimRewards）。
- 合约在 claimRewards 里会检查：若某笔 stake 已到期（`block.timestamp >= startTime + cycleDays * SECONDS_IN_UNIT`），就会对该笔 stake 调用 `_releaseDifferentialRewards(stakeId)`，把该 stake 对应的所有待发极差一次性发给链上各个上级。

因此：

- **下级一直不领收益** → 上级对应这笔质押的极差就**一直不会发**。
- **下级在周期结束后领收益** → 上级才会收到这笔极差（并收到 `DifferentialRewardDistributed` / `ReferralRewardPaid` 等事件）。

## 四、“没有极差奖励”常见原因汇总

| 情况 | 说明 |
|------|------|
| 以为“自己质押就有极差” | 极差是**下级质押、上级拿**；自己质押只产生静态收益和“作为上级被记极差”的资格。 |
| 没有下级或下级没质押 | 没有人在你下面质押，就不会有你对应的极差记录。 |
| 自己未激活 | 上级 `isActive == false`（自己从未成功质押过流动性），不会被记极差。 |
| 没有有效门票 | 上级门票为 0 或已 exited，不会被记极差。 |
| 团队人数不够等级 | V1 需 teamCount ≥ 10 才有 5%；否则 percent=0，不会产生极差。 |
| 下级还没领收益 | 极差要等**质押人**周期结束后点「领取收益」才会 _release，上级才会到账。 |
| 下级质押未到期 | 只有周期结束后的那次领取才会触发 _releaseDifferentialRewards。 |
| 数据迁移 | 旧合约的 stakePendingRewards 不会迁到新合约，只有新合约上新产生的质押才会记极差。 |

## 五、如何自查/排查？

1. **确认身份**  
   - 若你是**质押人**：你本来就没有“自己这笔质押的极差”，只有静态收益；要看你**上面的**人有没有极差。  
   - 若你是**上级**：要看你**下面**是否有人质押，且他们是否在周期结束后领过收益。

2. **看链上事件**  
   - 查你是否收到过 `DifferentialRewardDistributed(user=你的地址)` 或 `ReferralRewardPaid(user=你, rewardType=3)`。  
   - 若从未收到，说明要么没有符合条件的下级质押，要么下级还没领收益，要么你不满足上级条件。

3. **用脚本查**  
   - 使用 `scripts/check-user-differential-rewards.cjs`（把其中的用户地址改成要查的地址），可查该用户在新/旧合约的极差相关事件和等级信息。  
   - 注意：脚本里若使用 `getLevelByTeamCount`，需合约支持；当前合约多为 `getUserLevel(address)`，可改为调用 `getUserLevel(用户地址)` 获取等级和 percent。

4. **确认合约与迁移**  
   - 当前使用的是新合约还是旧合约？极差只对**当前合约上、该质押产生之后**的流程有效；旧合约未发放的极差不会自动迁到新合约。

---

**总结**：用户反馈“没有极差奖励”时，先区分是**质押人**还是**上级**，再对照上面“谁拿、何时发、条件、常见原因”逐条排查；多数情况是误解了“极差是上级拿的”或“要等下级领收益才发”。
