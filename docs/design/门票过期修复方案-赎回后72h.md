# 门票过期修复方案：赎回后 72h

## 一、问题

- **现象**：用户已打过流动性，赎回后门票被自动销毁，无法再次赎回。
- **原因**：当前只按「购票时间 + 72h」判断过期。赎回后无质押时，若购票已超过 72h，会立刻被判过期。
- **预期**：首次购票 72h 内须质押；**赎回后 72h 内须再次质押**，否则门票失效。

## 二、合约修改（JinbaoProtocolNative.sol）

### 2.1 新增存储

- 增加 `mapping(address => uint256) public lastStakeDeadlineBase;`
  - 含义：用户「最近一次变为 0 有效质押」的时间，作为 72h 截止的基准。
  - 为 0 时仍用 `purchaseTime`（首次购票 72h）。
- 将 `uint256[43] private __gap` 改为 `uint256[42] private __gap`，避免存储布局冲突。

### 2.2 redeem()

- 在函数末尾、`_updateActiveStatus` 之后：若 `_getActiveStakeTotal(msg.sender) == 0`，则  
  `lastStakeDeadlineBase[msg.sender] = block.timestamp;`

### 2.3 _handleExit()

- 在 `emit Exited` 之前（用户已无有效质押）：  
  `lastStakeDeadlineBase[user] = block.timestamp;`

### 2.4 _expireTicketIfNeeded()

- 当前逻辑：`if (block.timestamp <= t.purchaseTime + ticketFlexibilityDuration) return;`
- 改为：
  - `uint256 deadlineBase = lastStakeDeadlineBase[user] != 0 ? lastStakeDeadlineBase[user] : t.purchaseTime;`
  - `if (block.timestamp <= deadlineBase + ticketFlexibilityDuration) return;`

### 2.5 其他

- 首次购票不写 `lastStakeDeadlineBase`（保持为 0），仍用 `purchaseTime`。
- 再次质押时无需改 `lastStakeDeadlineBase`；下次赎回时会覆盖。

## 三、已受影响用户恢复（升级前已过期用户）

1. **导出列表**：`npx hardhat run scripts/export-ticket-expired-users.cjs --network mc --config config/hardhat.config.cjs`  
   输出见 `output/ticket-expired-*.json`（含 user、totalAmountMC、events）。
2. **恢复方式二选一或组合**：
   - **恢复门票**：对每条记录用 `adminSetUserTicket(user, ticketId, amount, purchaseTime, false)` 写回（ticketId 可用新值如 nextTicketId+1 或历史值；amount/purchaseTime 按导出或约定）。
   - **链下补偿**：按 JSON 中 `totalAmountMC` 从金库/多签给对应用户转 MC。

## 四、前端与文档

- 文案补充：「赎回后 72 小时内需再次提供流动性，否则门票失效。」
- 若有 72h 倒计时，在「无有效质押」时按 `lastStakeDeadlineBase`（或 0 时用 `purchaseTime`）计算截止时间。

## 五、升级注意

- 新变量通过 __gap 预留槽位加入，升级后旧数据不丢失，新变量默认为 0（行为与当前一致）。
