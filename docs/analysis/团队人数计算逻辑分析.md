# 团队人数计算逻辑分析

## 问题描述

修复脚本计算出的团队人数（52,113 和 101,708）偏大，需要分析计算逻辑是否正确。

## 合约中的 teamCount 定义

根据合约代码 `_updateTeamCount` 函数：

```solidity
function _updateTeamCount(address user) internal {
    address current = userInfo[user].referrer;
    uint256 iterations = 0;
    
    while (current != address(0) && iterations < 30) {
        uint256 oldCount = userInfo[current].teamCount;
        userInfo[current].teamCount = oldCount + 1;  // 只是 +1
        emit TeamCountUpdated(current, oldCount, oldCount + 1);
        
        current = userInfo[current].referrer;
        iterations++;
    }
}
```

**关键点**：
- 当新用户注册时，合约会在**推荐人链**上每个用户的 `teamCount` 上 **+1**
- `teamCount` 表示：**所有直接或间接推荐的用户总数**（不包括自己）
- 这是一个**简单的累加计数**，不是递归计算

## 修复脚本的计算逻辑

修复脚本 `fix-abnormal-accounts.cjs` 中的计算逻辑：

```javascript
async function calculateCorrectTeamCount(protocol, userAddress, visited = new Set(), depth = 0) {
    // 获取直推列表
    const directReferrals = await protocol.getDirectReferrals(userAddress);
    
    // 团队人数 = 直推人数 + 每个直推的团队人数
    let totalTeamCount = directReferrals.length;
    
    // 递归计算每个直推的团队人数
    for (const referral of directReferrals) {
        const referralInfo = await protocol.userInfo(referral);
        const referralTeamCount = Number(referralInfo.teamCount || 0);
        
        // 递归计算直推的团队人数
        const referralCalculatedCount = await calculateCorrectTeamCount(
            protocol, 
            referral, 
            new Set(visited), 
            depth + 1
        );
        
        // 使用较大的值
        const referralActualCount = Math.max(referralTeamCount, referralCalculatedCount);
        totalTeamCount += referralActualCount;  // ⚠️ 问题在这里！
    }
    
    return totalTeamCount;
}
```

## 问题分析

### 修复脚本的逻辑错误

修复脚本的计算公式是：
```
teamCount = activeDirects + Σ(每个直推的 teamCount)
```

这个公式是**错误的**，因为：

1. **重复计算**：
   - 如果用户 A 推荐了用户 B，用户 B 推荐了用户 C
   - 用户 A 的 `teamCount` 应该 = 2（B 和 C）
   - 但修复脚本会计算为：`1 + (B的teamCount=1) = 2`，这看起来是对的
   - 但如果用户 B 的 `teamCount` 已经是 1（包括 C），那么用户 A 的 `teamCount` 应该是 2，而不是 `1 + 1 = 2`

2. **实际应该是**：
   ```
   teamCount = 所有直接或间接推荐的用户总数
   ```
   这个值应该等于：从所有 `BoundReferrer` 事件中，`referrer = userAddress` 的用户总数（递归统计）

### 为什么数字会偏大？

修复脚本的计算方式会导致：
- 如果下级用户的 `teamCount` 已经包含了他们的下级，那么累加时就会**重复计算**
- 例如：
  - 用户 A 有 3 个直推：B, C, D
  - B 的 teamCount = 100（包括 B 的所有下级）
  - C 的 teamCount = 200
  - D 的 teamCount = 300
  - 修复脚本计算：`3 + 100 + 200 + 300 = 603`
  - 但实际上，A 的 teamCount 应该 = `3 + (B的下级数) + (C的下级数) + (D的下级数)`
  - 如果 B, C, D 的 teamCount 已经包含了他们的下级，那么累加就会重复计算

## 正确的计算方式

`teamCount` 应该等于：**所有直接或间接推荐的用户总数**

正确的计算方式应该是：
1. 从 `BoundReferrer` 事件中，找出所有 `referrer = userAddress` 的用户
2. 递归统计这些用户的所有下级用户
3. 总数 = 直接推荐数 + 间接推荐数

或者更简单的方式：
- 从所有 `BoundReferrer` 事件中统计
- 对于每个用户，如果他们的推荐人链中包含 `userAddress`，则计入 `userAddress` 的 `teamCount`

## 修复建议

### 方案1：使用事件统计（推荐）

```javascript
async function calculateCorrectTeamCount(protocol, userAddress) {
    const provider = new ethers.JsonRpcProvider(RPC_URL);
    const currentBlock = await provider.getBlockNumber();
    const fromBlock = Math.max(0, currentBlock - 1000000);
    
    // 获取所有 BoundReferrer 事件
    const boundEvents = await protocol.queryFilter(
        protocol.filters.BoundReferrer(),
        fromBlock
    );
    
    // 构建推荐关系图
    const referrerMap = new Map();
    boundEvents.forEach(event => {
        if (event.args && event.args.referrer && event.args.user) {
            referrerMap.set(
                event.args.user.toLowerCase(),
                event.args.referrer.toLowerCase()
            );
        }
    });
    
    // 递归统计所有下级用户
    function countRecursive(referrer) {
        let count = 0;
        for (const [user, ref] of referrerMap) {
            if (ref === referrer) {
                count += 1 + countRecursive(user);
            }
        }
        return count;
    }
    
    return countRecursive(userAddress.toLowerCase());
}
```

### 方案2：使用合约中的现有值（如果数据正确）

如果合约中的 `teamCount` 值本身是正确的（只是某些情况下没有更新），那么应该：
1. 检查哪些用户的 `teamCount` 确实不正确
2. 只修复那些真正有问题的用户
3. 使用事件统计的方式重新计算

## 当前修复结果的影响

虽然修复脚本的计算逻辑有误，但修复后的结果：
- ✅ 解决了"上级团队人数 < 下级团队人数"的逻辑错误
- ⚠️ 但可能导致某些用户的 `teamCount` 偏大
- ⚠️ 可能影响等级计算和奖励分配

## 建议

1. **立即检查**：验证修复后的 `teamCount` 是否合理
2. **重新计算**：使用事件统计的方式重新计算正确的 `teamCount`
3. **逐步修复**：如果发现数值偏大，需要重新修复
