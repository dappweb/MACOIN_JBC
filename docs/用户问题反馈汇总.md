# 用户提出问题的反馈汇总

## 一、流动性相关

### 1. 无法提供流动性

**问题**：部分用户反映无法购买/提供流动性。

**反馈**：
- **池子不足**：有待退金但协议 Swap 池 MC 不足时，无法质押。前端已增加质押前校验，会提前提示「协议池子暂时不足，无法退还您的待退金，请稍后再试或联系客服」。
- **门票过期**：购票后 72 小时内未质押，或赎回后 72 小时内未再次质押，门票会失效。需重新购票。
- **诊断工具**：可运行 `scripts/diagnose-liquidity-user.cjs [地址]` 排查具体原因。

---

### 2. 打了流动性后门票也销毁了 / 赎回不了

**问题**：用户已打过流动性，赎回后门票被销毁，无法再次赎回或质押。

**反馈**：
- **原因**：原逻辑仅按「购票时间 + 72h」判过期。赎回后若购票已超过 72h，会被立刻判过期。
- **已修复**：升级后增加「赎回后 72h」规则，以赎回时间为新 72h 起点。赎回后有 72 小时可再次质押。
- **已过期用户**：需人工恢复。可用 `scripts/export-ticket-expired-users.cjs` 导出名单，再通过 `adminSetUserTicket` 恢复门票或链下退 MC 补偿。

---

## 二、赎回相关

### 3. 赎回额外支付 1%

**问题**：赎回时 1% 如何收取、用户实收多少。

**反馈**：
- **规则**：用户实收 = 本金（全额）；需额外支付门票等额 1% 的 MC（不扣本金）。
- **实现**：赎回时 `msg.value` 需 ≥ 1% 总额，多付会退回。1% 进入待退池，再次质押时退还。
- **多笔质押**：因移除 `getRedeemPreview`，前端用 `feeBase × 1%` 估算；多笔时可能略偏低，建议多备少量 MC。

---

### 4. 系统有没有自动赎回功能

**问题**：系统是否会自动帮用户赎回。

**反馈**：
- **合约无自动赎回**：无 `redeemFor(user)`、无管理员代赎、无定时自动赎回。
- **赎回只能由用户发起**：用户需自己调用 `redeem()`。
- **被动退出**：用户达到 3 倍出局 cap 时，在领奖励或奖励分配时会自动触发 `_handleExit` 退出，这是合约内逻辑，不是后台主动代用户赎回。

---

## 三、门票过期与恢复

### 5. 前面好多门票自动销毁了，能恢复吗

**问题**：过期销毁的门票能否恢复。

**反馈**：
- **可恢复**：通过 `adminSetUserTicket` 写回门票状态，或按导出名单做链下 MC 补偿。
- **导出脚本**：`npx hardhat run scripts/export-ticket-expired-users.cjs --network mc --config config/hardhat.config.cjs`
- **输出**：`output/ticket-expired-*.json`，含 user、totalAmountMC、events 等。

---

### 6. 购票 / 赎回后的 72 小时规则

**问题**：门票何时失效。

**反馈**：
- **首次**：购票后 72 小时内须完成首次质押，否则门票失效。
- **赎回后**：赎回后 72 小时内须再次质押，否则门票失效。
- 详见：`docs/design/门票过期-修复前后对比.md`。

---

## 四、其他

### 7. 已购买 1000 MC 还能再买 1000 MC 吗

**反馈**：可以。合约与前端均允许再次购买同档位，门票金额会累加。

### 8. 升级后数据会不会丢失

**反馈**：不会。升级只替换实现逻辑，代理存储不变。新增变量通过 __gap 正确加入，旧数据保留。
