# V等级范围说明

## 当前等级标准

根据合约代码（`JinbaoProtocolNative.sol` 和 `JinbaoProtocolV2.sol`），V等级系统基于团队人数（teamCount）计算。

| 等级 | 团队人数要求 | 极差收益比例 | 说明 |
|------|------------|------------|------|

| **V1** | 10 - 29 | 5% | 极差奖励 |
| **V2** | 30 - 99 | 10% | 极差奖励 |
| **V3** | 100 - 299 | 15% | 极差奖励 |

## 等级计算逻辑

合约中的 `_getLevel` 函数实现：

```solidity
function _getLevel(uint256 value) private pure returns (uint256 level, uint256 percent) {
    if (value >= 100000) return (9, 45);  // V9: 100,000个地址，45%极差收益
    if (value >= 30000) return (8, 40);   // V8: 30,000个地址，40%极差收益
    if (value >= 10000) return (7, 35);   // V7: 10,000个地址，35%极差收益
    if (value >= 3000) return (6, 30);    // V6: 3,000个地址，30%极差收益
    if (value >= 1000) return (5, 25);    // V5: 1,000个地址，25%极差收益
    if (value >= 300) return (4, 20);     // V4: 300个地址，20%极差收益
    if (value >= 100) return (3, 15);     // V3: 100个地址，15%极差收益
    if (value >= 30) return (2, 10);      // V2: 30个地址，10%极差收益
    if (value >= 10) return (1, 5);        // V1: 10个地址，5%极差收益
    return (0, 0);                        // V0: 0-9个地址，0%极差收益
}
```

## 等级更新机制

- 等级在用户购买门票时自动计算和更新
- 当团队人数达到新的等级阈值时，等级会自动升级
- 等级变化会触发 `UserLevelChanged` 事件

## 注意事项

1. **等级是向下兼容的**: 如果团队人数达到V5，用户就是V5等级，即使团队人数继续增长
2. **等级不会降级**: 一旦达到某个等级，即使团队人数减少，等级也不会降低
3. **等级基于团队人数**: 等级完全基于 `teamCount`（团队人数）计算，与直推人数、收益等无关

## 数据不一致问题

根据数据一致性检查，发现部分用户的等级与团队人数不匹配：

- **问题**: 用户的团队人数已经达到更高等级的要求，但等级没有更新
- **原因**: 可能是等级更新逻辑没有正确执行，或者数据迁移时等级没有正确计算
- **解决**: 需要检查合约中等级更新的逻辑，确保等级能够正确自动更新
